## M3 — 데이터 정확성 대조

> **이 서비스의 신뢰도는 전부 데이터 정확성에 달려 있다.** (ToDo.md 7.3)

### 어떻게 확인하나

명세는 "화면에서 실거래 10건을 눈으로 대조"입니다. 표본이 적고 사람이 지치므로,
같은 조건의 **전 건을 자동으로 대조하는 명령**을 만들었습니다.

```bash
pnpm verify:molit --regions 41117 --from 2026-08-01 --to 2026-09-08
```

지역 코드는 시군구 5자리입니다 (강남구 11680 · 수원 영통구 41117 · 성남 분당구 41135).
기간을 빼면 최근 30일을 봅니다.

**왜 믿을 수 있나**: 우리 데이터는 공공데이터포털 **API** 로 받았고, 대조 상대는
국토부 실거래가 공개시스템 **웹** 입니다. 같은 원천이지만 전달 경로가 달라서
우리 파서·단위 변환·날짜 처리의 오류가 드러납니다.
같은 API 로 두 번 받아 비교하면 우리 실수는 절대 보이지 않습니다.

비교 항목은 명세 그대로 **계약일 / 전용면적 / 층 / 거래금액** 네 가지이고,
넷이 모두 같아야 한 건이 일치한 것으로 셉니다.

### 1차 결과 (2026-09-09)

| 지역 | 기간 | 국토부 | 일치 | 결과 |
|---|---|---|---|---|
| 서울 강남구 (11680) | 2026-07-01 ~ 09-08 | 230건 | 230건 | **100%** |
| 수원 영통구 (41117) | 2026-07-01 ~ 09-08 | 1,033건 | 1,033건 | **100%** |
| 성남 분당구 (41135) | 2026-07-01 ~ 09-08 | 591건 | 591건 | **100%** |

**계약일·전용면적·층·거래금액 1,854건 전 건 일치. 해제 유실 0건. → 합격.**

### 대조하다 찾은 것

#### ① 취소된 거래가 시세에 섞이고 있었다 (고침)

국토부는 같은 계약을 **두 줄로 줍니다** — 원거래 한 줄, 해제거래 한 줄.

```
동남 49.68㎡ 2026-08-13 14층 28,500만원   해제일 20260831
동남 49.68㎡ 2026-08-13 14층 28,500만원   해제일 -
```

중복 판정 지문에 해제 여부가 없어 두 줄이 같은 지문이 되고, 먼저 들어온 쪽이 남습니다.
원거래가 먼저 오면 **해제가 통째로 유실되어 취소된 거래가 살아 있는 것처럼 시세에 잡힙니다.**

→ 해제됐다는 사실을 덮어쓰도록 고치고, 서울·경기 3년치를 다시 훑어 바로잡았습니다.

**전체 규모: 해제 거래 11,716건 → 32,216건.**
즉 **20,500건(전체 거래의 3.3%)이 취소됐는데도 살아 있는 거래로 시세에 잡히고 있었습니다.**
2개월 표본에서는 지역당 1~4건으로 보였지만, 3년치로 보니 훨씬 컸습니다.
눈으로 10건을 봤다면 찾지 못했을 종류의 오류입니다.

수정 후 재대조: **1,854건 전 건 일치 · 해제 유실 0건 → 합격.**

#### ② 단지명 표기가 API 와 웹에서 다르다 (우리 오류 아님)

```
API : 강남브리즈힐(토지임대부아파트)
웹  : (토지임대부아파트)강남브리즈힐
```

값(계약일·면적·층·금액)이 모두 같으면 **표기 차이**로 따로 셉니다.
이걸 오류로 세면 없는 문제를 만들어내게 됩니다.
